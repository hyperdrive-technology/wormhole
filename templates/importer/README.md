# Wormhole importer template

A minimal, standalone importer project for [Wormhole](https://github.com/hyperdrive-technology/wormhole).
Copy it into your own repository (public or private), rename it, and replace the example
format with yours. It depends on `@wormhole/sdk` only.

The example converts **CSV tag lists** into IEC 61131-3 global variable declarations:

```csv
name,type,initial,comment
Motor_Run,BOOL,FALSE,Main conveyor motor running
Tank_Level,REAL,0.0,"Tank level, percent of span"
```

becomes `sources/<csv path without .csv>.plc`:

```iecst
(* Generated by example.csv-tags-importer 0.1.0 from tags.csv. *)
VAR_GLOBAL
    Motor_Run : BOOL := FALSE; (* Main conveyor motor running *)
    Tank_Level : REAL := 0.0; (* Tank level, percent of span *)
END_VAR
```

Columns are matched case-insensitively and extra columns are ignored. Rows that cannot be
converted (bad identifiers, unsupported types, initial values that are not a single
literal, duplicate names, malformed CSV) become error diagnostics with the file and line,
and are kept verbatim in `preservation/<csv path>.rejected.csv` so nothing is lost.
Legacy octal initial values (`8#17`) are upgraded to hex through `ctx.migrate`.

## Layout

| Path | What it is |
| --- | --- |
| `wormhole.importer.json` | Manifest: id, version, capabilities. Hosts read it without running your code. |
| `src/index.ts` | The importer: `detect()` and `import()`, default-exported via `defineImporter`. |
| `src/csv.ts`, `src/tags.ts` | Format-specific parsing and validation. Replace with yours. |
| `src/*.test.ts` | Unit tests and the conformance suite (`conformance.test.ts`). |
| `fixtures/` | Self-authored inputs used by the tests. |
| `.github/workflows/ci.yml` | Install, typecheck, test (unit + conformance), build. |

## Make it yours

1. Copy this directory into a new repository (without `node_modules/` and `dist/`).
2. Rename:
   - `package.json`: `name`, `description`, `version`.
   - `wormhole.importer.json`: `id` (dotted, lowercase, e.g. `acme.l5x-importer`), `name`,
     `description`, `version` (keep it equal to `package.json`; a test checks), `license`
     (an SPDX id, or `LicenseRef-<name>` for proprietary importers), and per capability
     `id` (prefix it with your vendor, e.g. `acme.l5x`), `displayName`, `vendor`,
     `vendorFamily`, `inputs.fileExtensions`, `inputs.mediaTypes`, `coverageNotes`.
   - `src/index.ts`: `CAPABILITY_ID` (must match the manifest) and the `Code` diagnostic
     prefixes (`EXAMPLE_CSV_` → something unique to you).
3. Replace `src/csv.ts`, `src/tags.ts`, the fixtures and the tests with your format.
4. Pick the SDK ref (next section), then `pnpm install` and commit `pnpm-lock.yaml`.

The importer contract in one paragraph: `detect()` must be cheap and deterministic (sniff
a few header bytes with `files.head()`, never parse whole files) and must not throw;
`import()` must be deterministic, must report bad input as diagnostics instead of throwing,
must keep what it cannot convert in `preservation/`, and must call `ctx.throwIfAborted()`
at the start and inside long loops. The conformance suite checks all of this.

## Getting `@wormhole/sdk`

`@wormhole/sdk` is not on npm. Depend on it **straight from GitHub**, as a subdirectory of
the public Wormhole repository:

```json
"dependencies": {
  "@wormhole/sdk": "github:hyperdrive-technology/wormhole#sdk-v0.1.0&path:/packages/sdk"
}
```

```yaml
# pnpm-workspace.yaml
allowBuilds:
  '@wormhole/sdk@git+https://github.com/hyperdrive-technology/wormhole.git': true
  esbuild: false
```

- `#sdk-v0.1.0` is a release tag. A commit SHA also works; `#main` works but moves.
- `&path:/packages/sdk` selects the SDK inside the monorepo.
- The `allowBuilds` entry is required. pnpm fetches the repository, installs its workspace,
  and runs the SDK's `prepare` script to build `dist/`. pnpm 12 refuses to run a git-hosted
  dependency's build scripts unless `pnpm-workspace.yaml` approves it
  (`ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`). The key is the repository URL without a commit,
  so it survives ref changes; the bare name `@wormhole/sdk` does not match a git-hosted
  package. pnpm 11+ ignores the old `package.json` `"pnpm": { "onlyBuiltDependencies" }`.
- `pnpm-lock.yaml` records the resolved commit. Commit it, so CI and every clone build
  against exactly the same SDK.
- Wormhole is public, so no token is needed, even when your importer repository is private.

To upgrade, change the ref, run `pnpm install`, run the tests, and commit `package.json`
and `pnpm-lock.yaml` together. When `@wormhole/sdk` is published to npm, switch to a
normal semver range.

## Scripts

```sh
pnpm install
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest: unit tests + conformance suite
pnpm build       # tsup → dist/index.js (the manifest's "entry")
```

`pnpm-workspace.yaml` holds the pnpm settings (pnpm 11+ no longer reads the `package.json`
`"pnpm"` field): `allowBuilds` lets pnpm build the GitHub-hosted SDK (see above) and skips
esbuild's optional install script (`esbuild: false`; tsup works without it). pnpm 12 fails
an install on any build script that is neither approved nor denied there.

## Conformance in CI

`src/conformance.test.ts` calls `describeImporterConformance` from
`@wormhole/sdk/conformance/vitest`, which registers one test per check: manifest valid,
detect deterministic and cheap, outputs schema-valid, output paths safe, archives
byte-identical across runs, abort and limits honoured, garbage input diagnosed. It runs as
part of `pnpm test`, so the included workflow enforces it on every pull request. Give it
two or three representative fixtures; the kit derives the garbage, truncated and CRLF
variants from them.

## Keeping a private importer private

- Keep `"private": true` in `package.json` so it is never published by accident.
- **Never commit customer or vendor project files** as fixtures, even in a private
  repository: fixtures end up in CI logs, caches and every clone. Write small synthetic
  inputs that exercise the same constructs, as `fixtures/` does here.
- Diagnostics and logs should name files and lines, not echo large chunks of input.
- The SDK comes from the public Wormhole repository, so CI needs no registry or GitHub tokens.
